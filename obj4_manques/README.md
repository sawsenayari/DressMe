# DressMe: Wardrobe Gap Detection and Shopping

This package implements the DressMe **wardrobe-gap detector**. Its purpose is
to analyze the user's existing wardrobe, identify missing clothing pieces that
could create many additional outfits, rank those missing pieces, and optionally
find online shopping options for the most valuable gaps.

The package is designed to work with the other DressMe objectives:

- **Objective 1 - Wardrobe understanding:** provides the wardrobe inventory,
  item metadata, categories, slots, images, and FashionCLIP embeddings.
- **Objective 2 - Compatibility:** scores whether two clothing items work
  together through the `/pairs` service.
- **Objective 4 - Gap detection:** uses compatibility scores and deterministic
  outfit counting to rank missing wardrobe pieces.
- **Objective 5 - Outfit recommendation:** can consume compatible wardrobe
  items and gap information when constructing complete outfits.
- **Objective 6 - Orchestration/application integration:** can consume the
  versioned gap output and expose the result through the application.

Objective 4 remains responsible for detecting and ranking gaps. The optional
shopping feature is a separate presentation layer and must not modify the
compatibility scores or the outfit-counting logic.

## What the system does

The current workflow has these stages:

1. Load a FashionCLIP wardrobe inventory.
2. Load the row-aligned FashionCLIP embedding cache.
3. Load textual gap candidates generated by the LLM.
4. Give each text candidate a transparent same-slot wardrobe-image proxy.
5. Send wardrobe and candidate pairs to Objective 2 `/pairs`.
6. Convert Objective 2 scores to compatibility verdicts.
7. Count outfits deterministically with the Python outfit engine.
8. Compute conservative and optimistic outfit-gain bounds.
9. Rank candidates by gain.
10. Optionally search the web for buying options for the highest-ranked gaps.
11. Optionally display those results in a local browser interface.

The old static `gap_report.json` is a **fallback only**. It must not replace a
newer completed Objective 2-backed analysis.

## Important limitation: candidate proxies

The LLM generates textual candidates such as:

> Classic white button-down shirt

A text description does not contain a FashionCLIP image embedding. Until the
team agrees on a real synthetic-item representation or supplies representative
candidate images, Objective 4 uses a deterministic same-slot wardrobe item as
a proxy.

The output records:

```json
{
  "representation": "wardrobe_image_proxy",
  "proxy_item_id": "wardrobe-0190"
}
```

This makes the result operational and auditable, but it does not mean that the
proxy is a true visual embedding of the proposed product. The ranking should
therefore be described as **proxy-based** until this representation is
approved and calibrated.

## Important limitation: calibration

The default score thresholds are currently:

- `score >= 0.70`: compatible
- `score < 0.40`: incompatible
- Between those values: uncertain

These are placeholders until the team calibrates them on a shared evaluation
set. The generated output explicitly reports:

```json
"calibration_status": "thresholds_not_yet_team_calibrated"
```

The deterministic outfit engine is the numerical source of truth for outfit
counts. Objective 2 scores are compatibility evidence, not outfit counts by
themselves.

## Required project layout

The commands below assume this layout:

```text
PIDS5/
  .env
  .venv/
  dressme_gap_agent/
  dressme_compat_service/
  wardrobe/
    .dressme-cache/
      full/
        wardrobe_inventory.json
        fashionclip_embeddings.npz
      llm-gap-v1/
        gap_archetypes.json
  tests/
```

The active inventory contains the FashionCLIP item records. The embedding
cache must have matching item IDs and 512-dimensional FashionCLIP vectors.
Objective 2 expects FashionCLIP embeddings from
`patrickjohncyh/fashion-clip`, not standard CLIP embeddings.

## Start the Objective 2 service

From the repository root, run:

```powershell
.\.venv\Scripts\python.exe -m uvicorn app:app --app-dir .\dressme_compat_service --port 8002
```

Check that it is available:

```powershell
Invoke-WebRequest http://127.0.0.1:8002/health
```

The service exposes:

- `GET /health`
- `POST /compat`
- `POST /pairs`

Objective 4 uses `/pairs`.

## Run the Objective 2-backed gap pipeline

From the repository root:

```powershell
.\.venv\Scripts\python.exe -B -m dressme_gap_agent.objective2_gap_pipeline `
  --inventory .\wardrobe\.dressme-cache\full\wardrobe_inventory.json `
  --embeddings .\wardrobe\.dressme-cache\full\fashionclip_embeddings.npz `
  --candidates .\wardrobe\.dressme-cache\llm-gap-v1\gap_archetypes.json `
  --output .\wardrobe\.dressme-cache\objective2_gap_analysis.json `
  --base-url http://127.0.0.1:8002 `
  --score-cache .\wardrobe\.dressme-cache\objective2-pairs.json `
  --timeout 120
```

The result is written to:

```text
wardrobe/.dressme-cache/objective2_gap_analysis.json
```

The result includes:

- pipeline status;
- whether the ranking is ready;
- number of inventory items;
- number of candidates;
- Objective 2 request count;
- thresholds and calibration status;
- candidate descriptions and rationales;
- proxy representation and proxy item IDs;
- conservative `gain_lower`;
- optimistic `gain_upper`;
- final rank.

The current ranking is not scientifically final while proxy representation and
compatibility thresholds remain uncalibrated.

The output also includes `contract_version: "1.0"` and
`compatibility_progress`, so it can be validated by
`dressme_gap_agent.contracts.validate_gap_result` before Objective 6 consumes
it.

## Run the shopping search from the terminal

The shopping stage uses only the completed gap analysis. It does not rerun
Objective 2 and does not change the gap ranking.

```powershell
.\.venv\Scripts\python.exe -B -m dressme_gap_agent.shopping `
  --analysis .\wardrobe\.dressme-cache\objective2_gap_analysis.json `
  --output .\wardrobe\.dressme-cache\shopping_recommendations.json `
  --gap-limit 3 `
  --max-results 5 `
  --max-price 100
```

The output is written to:

```text
wardrobe/.dressme-cache/shopping_recommendations.json
```

The result contains:

- the ranked gap;
- slot and rank;
- search options;
- page title;
- source URL;
- search snippet;
- a detected price when available;
- an optional image URL;
- the search provider.

Prices are extracted from web snippets and are not guaranteed to be the final
price. The user must verify product identity, color, size, availability,
shipping, taxes, and final price on the retailer page.

## Run the browser interface

The browser interface is a local testing UI. It keeps the Tavily API key on
the server and does not send the key to the browser.

```powershell
.\.venv\Scripts\python.exe -B -m dressme_gap_agent.web_app
```

Open:

```text
http://127.0.0.1:8765
```

The interface allows the tester to choose:

- how many ranked gaps to search;
- how many results to request per gap;
- a maximum price.

Press `Ctrl+C` in the server terminal to stop it.

The search provider may return no reliable product photo. The application
tries provider image results and product-page Open Graph images, but retailers
may block image access or return editorial images instead of product photos.
The UI must never invent an image or present an unrelated image as a verified
product photo.

## Safe cleanup and file review

Before removing files, determine whether they are:

1. imported by Python code;
2. referenced by tests;
3. required by a documented command;
4. an active cache or generated output;
5. a fallback explicitly required by the application;
6. a teammate integration contract;
7. a duplicate or obsolete artifact.

Do not delete the following without team approval:

- Objective 1 inventory files;
- FashionCLIP embeddings;
- Objective 2 service files;
- active cache files needed to reproduce a result;
- `gap_report.json`, because it remains a documented fallback;
- contract schemas;
- tests;
- `.env` or any credential file.

Generated caches may be regenerated, but first verify their producing command
and whether another teammate depends on them. Prefer moving an uncertain file
to a clearly named archive outside the active runtime path rather than deleting
it immediately. After cleanup, run the complete test suite and rerun the
pipeline commands.
